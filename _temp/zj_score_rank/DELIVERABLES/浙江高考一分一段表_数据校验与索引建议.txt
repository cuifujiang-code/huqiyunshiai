## 数据库建表索引优化建议

### 建表 DDL（PostgreSQL 推荐）
```sql
CREATE TABLE zhejiang_gaokao_score_rank (
    id           SERIAL PRIMARY KEY,
    exam_year    SMALLINT NOT NULL,
    score        SMALLINT NOT NULL,
    rank         INTEGER NOT NULL,
    section_num  INTEGER NOT NULL DEFAULT 0,
    category     VARCHAR(10) NOT NULL DEFAULT '普通类',
    subject_type VARCHAR(10) NOT NULL DEFAULT '综合类',
    batch        VARCHAR(10),
    rank_percent NUMERIC(8,4) NOT NULL DEFAULT 0,
    total_student INTEGER NOT NULL,
    created_at   TIMESTAMP DEFAULT NOW()
);
```

### 核心联合索引（按查询频率排序）

1. **主查询索引（覆盖90%场景）**
   志愿填报系统最常见的查询是"给定年份+分数，查位次"或"给定位次，查对应分数"
   ```sql
   CREATE INDEX idx_year_score ON zhejiang_gaokao_score_rank
       (exam_year, score DESC, rank);
   ```

2. **分类查询索引**
   未来扩展艺术类/体育类、物理类/历史类数据时启用
   ```sql
   CREATE INDEX idx_year_cat_subj_rank ON zhejiang_gaokao_score_rank
       (exam_year, category, subject_type, rank);
   ```

3. **位次区间查询索引**
   志愿系统需要按位次区间筛选（如 top 10%/20%）
   ```sql
   CREATE INDEX idx_rank_percent ON zhejiang_gaokao_score_rank
       (exam_year, rank_percent);
   ```

4. **分数区间查询索引**
   ```sql
   CREATE INDEX idx_score_range ON zhejiang_gaokao_score_rank
       (exam_year, category, subject_type, score DESC);
   ```

### 索引策略说明
| 场景 | 推荐索引 | 原因 |
|------|---------|------|
| 分数→位次 | idx_year_score | exam_year + score DESC 直接命中 |
| 位次→分数 | idx_year_cat_subj_rank | rank 排序查询 |
| 位次百分比筛选 | idx_rank_percent | 范围查询高效 |
| 批次筛选(一段/二段) | idx_year_score + 应用层过滤 | batch 选择性低，不适合单独建索引 |

### 注意事项
- 当前浙江省数据约 1281 行，直接全表扫描性能也完全足够
- 当数据扩展到全国 31 省份后（预计 50万+ 行），上述索引可保证毫秒级响应
- SMALLINT 用于年份和分数（节省50%存储），INTEGER 用于位次
- NUMERIC(8,4) 用于 rank_percent 保证精度（0.0000 ~ 1.0000）
